# 玄玑 Market Trace｜A股百亿成交触板与次日溢价

玄玑旗下的响应式市场样本观察网站，持续追踪当日最终成交额不低于 100 亿元且盘中触及涨停价的 A 股样本，并提供玄玑微信小程序入口。

在线访问：[Market Trace 市场样本观察](https://ymj8903668-droid.github.io/market-trace/)

网站支持在沪深300、上证指数和中证1000之间切换。指数涨跌方向通过数据点外圈表达，并同步更新上涨日/下跌日样本的次日平均开盘溢价与悬停详情。

图表中的涨停收盘、炸板、触板顺序和指数涨跌日均可独立勾选显示。组合筛选采用“类别内并列、维度间同时满足”的口径，并实时更新当前样本数、筛选均值与极值标注；上方市场环境汇总始终保持全样本口径。

页面提供近 1 个月、近 2 个月和今年以来三个观察窗口，默认显示近 1 个月。当前数据已回补到 2026 年 1 月 1 日，并以最近一个具备完整次日开盘行情的触板交易日作为统计终点。

## 本地运行

```bash
npm install
npm run dev
```

## 生产构建

```bash
npm run build
```

构建产物位于 `dist/`，可部署到任意静态网站托管服务。Vite 会在 GitHub Actions 中自动使用仓库子路径，本地构建则保留相对资源路径。

仓库内置 GitHub Pages 工作流。每次推送到 `main` 都会依次执行依赖审计、自动测试、生产构建和公网部署；Pull Request 只执行质量检查，不发布生产版本。

## 数据更新

本地更新需要通过环境变量提供 Tushare Token，Token 不会写入数据文件、日志或 Git 历史：

```bash
TUSHARE_TOKEN=*** npm run data:update
```

GitHub Actions 在工作日北京时间 18:35 自动运行 `.github/workflows/update-market-data.yml`。流程会依次拉取数据、交叉校验成交额、运行测试和依赖审计、构建网站；只有数据发生变化时才提交生成文件并部署 GitHub Pages。自动化使用仓库 Actions Secret `TUSHARE_TOKEN`。

## 自动更新与告警

- **更新失败告警：**主更新任务无论在哪个质量门禁失败，都会创建或更新 `🚨 Market Trace 自动更新失败` Issue，并指派给仓库所有者；恢复后自动关闭。
- **独立断更巡检：**工作日北京时间 21:30 运行 `.github/workflows/monitor-market-data.yml`，通过上交所交易日历核对仓库中的 `updatedAt`。节假日沿用最近开市日，不会仅按自然日误报。
- **断更告警：**巡检发现数据落后时，创建或更新独立的 `🚨 Market Trace 数据断更` Issue；恢复后自动关闭。Issue 指派和 @ 提及会按 GitHub 账号的通知设置发送邮件。

收到告警后，依次检查 Actions 运行记录中的 `Refresh audited market data`、`Audit dependencies`、`Commit refreshed data` 和 `Deploy to GitHub Pages`。不要跳过安全审计；依赖漏洞应更新锁文件并通过完整测试后再恢复发布。

## 数据口径

- 样本：Tushare 涨停/炸板明细中的 U（涨停收盘）与 Z（炸板）。
- 成交额：用日线行情复核当日最终成交额不低于 100 亿元。
- 触板顺序：同日合格样本按首次触板时间升序做密集排名，同秒并列。
- 次日开盘溢价：次一交易日开盘价 ÷ 次日前收盘价 − 1。
- 指数环境：触板当日指数收盘涨跌幅；上涨/下跌分组按股票只次统计，不按交易日等权。
- 完整性边界：只发布已经取得次一交易日开盘价的触板样本，因此统计终点通常比“数据更新日”早一个交易日。
- 本站为历史样本研究，不构成投资建议。

数据字段说明见 [`DATA_SCHEMA.md`](./DATA_SCHEMA.md)。
